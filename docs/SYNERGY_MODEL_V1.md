**Scope:** The synergy architecture — contexts, coupling rules, manager engines, player anatomy, posture system, match resolution, run curve. Numbers marked ⚗️ are sim-validated baselines (`scripts/balance_sim.py`), not final tuning.

## 1. Design laws

These are invariants. Any card, trait, or system that violates one is wrong by definition.

1. **No unconditional bonuses.** Every trait must reference a context, trigger, or resource. No card is good everywhere. This is the rule that forces synergy to exist.
2. **Loose coupling only.** Managers and players never reference each other by name or archetype. Managers reweight *contexts*; players reference *contexts*. Emergent synergy comes from the shared vocabulary.
3. **Closed palettes.** All mechanics are expressed over the closed verb palette (10 verbs, per `KICKOFF_CLASH_DESIGN.md`) × the closed context taxonomy (§2). New content = new combinations, not new primitives.
4. **Managers are TraitRecords.** No manager object in code. A manager is a bundle of TraitRecords that sets a default posture, a preferred formation, and reweights contexts. Preserves the no-archetype-object commitment.
5. **Dual-axis compounding.** ⚗️ Every engine must be able to grow on two axes via the shop: *consistency* (window conversion) and *amplification* (payout value). Compounding on one axis cannot chase the target curve — sim-proven (beat rate ~1% single-axis vs ~45% dual-axis). Shop stock and trait templates must serve both axes.

## 2. Context taxonomy (closed, v1 = 10)

Inclusion test: (a) engine can detect/declare it unambiguously, (b) ≥2 manager engines can plausibly weight it.

### Postures — declared states, never inferred. One active per side per increment.

| Context | Notes |
| -- | -- |
| `possession` | Controlling tempo |
| `deep-block` | Low line, own third |

(Additional postures may be added in v2 — e.g. high-press as a posture rather than a card — but v1 ships with two plus tactical-card windows.)

### Phases/events — generated by the engine from the posture matchup.

| Context | Generation |
| -- | -- |
| `transition` | Turnover window; rate driven by posture matchup matrix |
| `set-piece` | Event + resolution window; rate up when possession meets deep-block |
| `goal-event` | scored / conceded (maps to existing `onGoal`/`onConceded` hooks) |
| `substitution` | Instantaneous trigger |

### States — evaluated per increment, stackable.

| Context | Values |
| -- | -- |
| `scoreline` | leading / level / chasing |
| `clock` | early / mid / late bands |
| `streak` | consecutive engine successes (goals, clean batches, counters) |
| `fitness` | above/below thresholds, squad or player |

**Cut, with reasons:** `home/away` (uncontrollable variance, fails test b as a trait context — lives in challenge rules instead). `formation` (already its own subsystem — the adherence throttle, §7 — double-counting if also a trait context).

## 3. Posture system

* Manager sets the **default posture**. It is always active unless overridden. Engines must run on a bad hand — no mulligan misery.
* **Tactical cards are the only deviation mechanism.** Playing one opens a **timed window** (duration is a card stat, rarity-scalable), after which posture **reverts to the manager's default**.
* **Event generation is a function of the posture matchup** (yours × opponent's). The matchup matrix is data. Example: my `deep-block` vs their `possession` → elevated `transition` window rate for me, elevated `set-piece` rate for them.
* **Opponents are posture profiles + a small engine.** The matchup matrix *is* the opponent system.

## 4. Managers

A manager defines **how you are allowed to win**: a win-condition engine over contexts, a default posture, a preferred formation.

* **Run start: choice of three.** Identity is known from minute one; every draft decision filters through it.
* **Shop pivots:** managers appear in shops **rarely** and **priced above pivot break-even** — buying one mid-run should cost ~2 shops of player purchases. The organic pivot tax (your squad's traits go partially dead) is real but survivable under loose coupling; the price compounds it. Cheap managers → all runs converge on strongest engine → run identity dies.
* **Legibility rule:** every manager's win condition must be statable in one line. If it can't, it's not a v1 manager. (Selection screen *and* ten-second mid-run pivot evaluation.)

### v1 roster (10)

| Manager | One-line win condition | Core contexts | Default posture |
| -- | -- | -- | -- |
| Counter-Attack | Win the ball, score within the window, chain counters | transition, streak | deep-block |
| Set-Piece | Corners and free kicks are your entire offense | set-piece, streak | deep-block |
| Fortress | Clean-sheet minutes bank points; a 0-0 can win | deep-block, clock, streak | deep-block |
| Tinkerman | Substitutions fuel the engine | substitution, fitness, clock | possession |
| Metronome | Unbroken possession compounds | possession, streak | possession |
| Chaser | Engine only ignites level/behind, late | scoreline, clock | possession |
| Gambler | Everything swingy, both directions | amplify-variance over all | possession |
| Pragmatist | Narrow, grinding, reliable 1-0s | dampen-variance over all | deep-block |
| Taskmaster | Output bought with player fitness | fitness (drain), streak | possession |
| Financier | Weak on pitch; results generate extra cash | goal-event, economy | possession |

All 10 verbs and all 10 contexts are load-bearing across the roster; Gambler/Pragmatist are the sole consumers of the variance verbs (mechanically: they change the resolution die, §6). Financier's precise role: shortens the distance to affording a pivot.

⚗️ **Tuning flag:** accrual engines (Fortress-type) scale smoother than streak engines and trend dominant — first calibration had Fortress at 98% mid-run survival. Keep accrual engines on the tightest balance leash. Target identity: the run-preserver, dying late but rarely early.

## 5. Player card anatomy

A player card is exactly:

1. **Base contribution** — deliberately mediocre at every rarity. The "incomplete on its own" guarantee.
2. **1–2 conditional traits** — TraitRecords: (verb, context, magnitude tier). All real value lives here and only pays out under the right regime.
3. **Cluster tag** — which chemistry cluster (spine, left flank, right flank, front line, bench) the card slots into. Feeds cluster synergy (later phase).

**Rarity scales conditionality, not numbers.** Commons: one broad, weak trait. Legendaries: narrow, violent, build-locked traits. A Legendary offered to the wrong build is genuinely skippable.

### Dataset regeneration (500 cards)

* **Trait templates, not free generation.** ~25–30 closed templates, each a (verb, context, magnitude-tier) tuple. QA reviews 30 templates, not 500 cards.
* Assignment by position/profile heuristics from existing `kc_characters.json` data. Magnitude tier from rarity.
* **Coverage validation post-pass:** every manager engine must have fuel at every rarity band (e.g. ≥~15% of Commons carry a transition trait). Script emits traited dataset + coverage report. Deterministic, seeded, re-runnable.
* **Legendaries hand-authored** (~20–30 cards, signature abilities). Serve dual-axis law: templates must exist for both consistency and amplification on every major context.

## 6. Match engine

**Step-resolved.** 6 batches × 3 increments (18 resolution events ⚗️ — 9 was too swingy). Tactical cards played between batches. Energy budget per match (v1: 5).

### Window resolution ("playing a hand")

`squad charge (relevant traits) + d(die) ≥ threshold` → converted.

* **Default die: d4.** ⚗️ Variance verbs change die size — d4→d8 at a knife-edge fixture swings win probability ~10pp (99%→89%). Real teeth, not dominant.
* Windows are **presented as choices**: commit (spend fitness/energy where applicable) or let it pass. No empty turns — every generated event is a decision.
* Opponent posture shifts telegraphed one batch ahead.

### Scoring: goals AND points, no conversion

* **Goals are real events on a real scoreline.** Each goal banks `streak-mult × goal-value` **points**. Fixture target is points.
* Scoreline = what happened (honest football, win 2-1). Points meter = was it enough. Fortress's 0-0 win: clean-sheet accrual banks points goallessly; scoreboard truthfully reads 0-0.
* **Early whistle:** full-time when target met. Surplus energy/batches convert to cash (Balatro remaining-hands economy hook).

### Streaks

* Reset on **engine-contradiction** (the thing your engine is trying to prevent): Counter-Attack on conceding; Metronome on turnover conceded; Fortress clean-clock on conceding. Per-match; never persist across matches in v1.
* **No point subtraction on concede.** ⚗️ A/B tested: ±3–7pp, within noise. The streak reset *is* the punishment. Reset-only — cleaner rules, equal bite.
* Streak-break UI must state the reason in engine terms ("Streak broken: conceded"). The failure mode teaches the win condition.
* Opponent runs a visible streak/engine of its own. A race, not a wall.

## 7. Formation adherence

Three bands, not a sliding scale (band-drop is legible in a ten-second shop decision; percentages aren't):

| Band | Definition | Engine output |
| -- | -- | -- |
| Native | Manager's preferred formation | 100% |
| Adjacent | One structural step away (adjacency defined per formation, in data) | ~70% |
| Foreign | Anything else | ~40% |

Mechanically: adherence throttles the default posture's event-generation weights. Exact percentages are a balance pass.

## 8. Run structure

* **9 fixtures.** Challenge rules from fixture 2–3. Boss fixture every third (harshest rule + manager/legendary-weighted shop after).
* **Target curve:** ⚗️ `points_target(f) = 1.8 × 1.42^f`. Validated shape: uncommitted-but-good squads die at median fixture 5 with 54% of deaths inside the 5–7 wall and 0% run completion; committed engines reach median fixture 9 with 41–49% run-beat. These are acceptance-criterion distributions for the implementation, not vibes.
* Fixture card shows opponent posture profile, challenge rule, reward — before selection.

## 9. Feedback requirements (non-optional; the feedback is the strategy surface)

**Selection screen:** every squad card's traits pre-evaluated against the current regime — lit (engine feeds it) / dim (dormant) / red (killed by challenge rule). Dead cards visible before kickoff.

**In match:** persistent streak meter with projected payout (the performance centerpiece); per-increment trait-proc toasts; goals annotated with engine math ("Counter ×3 — 6 pts").

**Post-match dashboard:** trait uptime per player ("active 12% of match" = which cards are dead), window count vs conversion rate (engine vs parts diagnosis), streak peaks, break reasons, cash. Losses must diagnose themselves into next-run hypotheses.
